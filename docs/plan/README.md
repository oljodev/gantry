# Gantry — architecture plan

**Status:** draft v3, 2026-09-05. Session 1 produced documents 01–09; session 2 added 10–14 and folded them into the roadmap; session 3 designed and built the marketing site (14, `website/`). This is the planning baseline for the from-scratch rebuild. It is a plan, not a spec frozen in stone: when implementation contradicts it, update the plan in the same commit.

Gantry is a cross-platform desktop app (macOS, Windows, Linux) that combines a general AI chat client, a coding-agent environment, research tooling and an extensible connector (MCP) system in one Tauri/Rust/React application. Bring-your-own-key only. Local storage only in v1.

## Decision register

Decisions the rest of the plan depends on. Each is justified where it is used.

| ID | Decision | Choice |
|----|----------|--------|
| D1 | Application shell | Tauri 2.11.x, Rust backend, React 19 frontend (given) |
| D2 | MCP client | The official Rust SDK `rmcp` (3.x), wrapped behind a Gantry adapter. No hand-written MCP client. |
| D3 | Sidecar processes | None bundled. Third-party MCP servers run as ordinary child processes on runtimes the user installs (Node, Python/uv, Docker); Gantry detects and guides. An optional on-demand Node runtime download is a post-MVP item. |
| D4 | Model provider layer | Gantry's own thin `Provider` trait with four client implementations: Anthropic Messages, OpenAI Responses, OpenAI-compatible Chat Completions (xAI, OpenRouter, custom), Gemini Interactions. |
| D5 | Local storage | SQLite through `rusqlite` (bundled SQLite, WAL, FTS5, JSON) plus a content-addressed blob directory. |
| D6 | Credential storage | One random master key in the OS credential store (Keychain / Credential Manager / Secret Service via the `keyring` crate family); every secret envelope-encrypted with it and stored in SQLite. Secrets never cross the IPC boundary. |
| D7 | IPC | Typed commands generated by `tauri-specta`; one Tauri `Channel` per agent turn for streaming; global events only for cache invalidation. |
| D8 | Frontend stack | Vite, TypeScript strict, Tailwind v4, shadcn/ui on Base UI, TanStack Router + Query + Virtual, Zustand for high-frequency run state, CodeMirror 6 for diffs and editors. |
| D9 | Permission modes | Manual, Auto-edit, Plan, Auto. Auto is one mode with a **Guard** setting (Judge on by default, or Off). Permissions are stored per chat. A sixth risk tier, `app`, covers tools that only touch Gantry's own state. |
| D10 | Judge | The cheapest fast model of whichever provider the chat already uses (overridable); structured allow/deny decision; falls back to a blocking prompt if the judge itself fails. |
| D11 | Connector packaging and installation | `connectors/<id>/manifest.json` for every connector; native connectors are Cargo crates in the same folder; manifests are embedded at build time and form the catalog. **Nothing is installed without an explicit Install action**, first-party connectors included. |
| D12 | License | Functional Source License, FSL-1.1-ALv2 (converts to Apache 2.0 two years after each release). |
| D13 | System prompt | A fixed core scaffold plus additive, size-limited instruction layers (global, project, chat) and pinned skills; never replaced, only appended; precedence rule in the core. |
| D14 | Theming | CSS tokens with the three-state light/dark/system pattern; the Tauri window theme is set alongside so native chrome matches; choice stored in settings and mirrored for first paint. |
| D15 | Skills | Text only, Agent Skills-compatible `SKILL.md` with Gantry fields under `metadata`; keyword matching plus model-driven loading; write / export / import / AI-proposed flows; community catalog deferred. |
| D16 | Memory | SQLite table, fully visible and editable on a Memory page; the assistant proposes and the user confirms (non-blocking); two-tier selection with fixed token budgets. |
| D17 | Artifacts | Created through `gantry__create_artifact`/`update`/`edit` tools in the normalized tool layer; six v1 types; executable types run in an opaque-origin `srcdoc` iframe with `sandbox="allow-scripts"` and a strict CSP; React compiled in-sandbox with Babel and loop protection; linear immutable versions; chat-owned, project-visible. |
| D18 | Catalog distribution | The curated connector catalog ships statically with each release; a signed remote overlay is designed but deferred. |
| D19 | Public sites | Marketing site in `website/` at `oljo.dev`: an Astro 7 static site (Tailwind 4, one React island for the hero mock, Starlight for docs) with a company-style sitemap; MCP client metadata in `client-metadata/` at `id.oljo.dev`; two Cloudflare Pages projects; download buttons use stable asset names and `releases/latest/download/` URLs, enabled through the GitHub releases API. |
| D20 | Site visual system | Dark only, Linear/Vercel style: neutral zinc ground, Gantry orange `#ff7a1f` as the one accent, Geist and Geist Mono self-hosted, a floating pill navbar with menus, reveals plus a few scroll-linked figures, a Ramp-style connector logo cloud, connector marks from Simple Icons in their own colours (initials where none exists). Tokens live once in `website/src/styles/theme.css`. 14 §2, §4. |

## Vocabulary

- **Chat** — one conversation. Owns its permission mode, attached connectors, grants, workspace roots, instructions and artifacts.
- **Project** — a named group of chats with instructions, knowledge files, defaults, pinned skills and an optional workspace folder.
- **Turn** — the unit of agent work: one user message and everything the assistant does until it stops (possibly many model calls and tool calls).
- **Transcript** — the append-only, provider-neutral list of messages a chat replays to the model.
- **Event** — one append-only, timestamped record of something that happened during a turn; the activity feed is a rendering of events.
- **Connector** — a catalog entry (`connectors/<id>/`). **Instance** — an installed, configured connector. **Tool** — one callable capability a connector exposes. **Runtime tool** — a tool owned by the app itself (`gantry__…`), not by a connector.
- **Interaction** — a pending decision the user must make (permission, access request, connector suggestion, MCP elicitation, skill or memory proposal). One mechanism serves all of them.
- **Skill** — a text-only `SKILL.md` playbook injected into context when relevant. **Memory** — a short, user-visible fact or preference carried across chats.
- **Artifact** — a versioned piece of content (document, code, page, diagram, component) shown in the panel beside the chat.
