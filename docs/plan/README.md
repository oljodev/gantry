# Gantry — architecture plan

**Status:** draft v3, 2026-09-05. Session 1 produced documents 01–09; session 2 added 10–14 and folded them into the roadmap; session 3 designed and built the marketing site (14, `web/site/`); session 5 decided the application design system (15); session 7 planned the first-party connectors in `docs/connectors/` and split the app into two surfaces (16); session 8 researched the third-party catalogue and planned its rollout (17). This is the planning baseline for the from-scratch rebuild. It is a plan, not a spec frozen in stone: when implementation contradicts it, update the plan in the same commit.

Gantry is a cross-platform desktop app (macOS, Windows, Linux) that combines a general AI chat client, a coding-agent environment, research tooling and an extensible connector (MCP) system in one Tauri/Rust/React application. Bring-your-own-key only. Local storage only in v1.

## Decision register

Decisions the rest of the plan depends on. Each is justified where it is used.

No hand-written MCP client.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| D3  | Sidecar processes                    | None bundled. | D5  | Local storage                        | SQLite through `rusqlite` (bundled SQLite, WAL, FTS5, JSON) plus a content-addressed blob directory.                                                                                                                                                                                                                                                                                                                                                                                                                                       |

## Vocabulary

- **Chat** — one conversation. Owns its permission mode, attached connectors, grants, workspace roots, instructions and artifacts.
- **Project** — a named group of chats with instructions, knowledge files, defaults, pinned skills and an optional workspace folder.
- **Turn** — the unit of agent work: one user message and everything the assistant does until it stops (possibly many model calls and tool calls).
- **Transcript** — the append-only, provider-neutral list of messages a chat replays to the model.
- **Event** — one append-only, timestamped record of something that happened during a turn; the activity feed is a rendering of events.
- **Connector** — a catalog entry (`desktop/connectors/<id>/`). **Instance** — an installed, configured connector. **Tool** — one callable capability a connector exposes. **Runtime tool** — a tool owned by the app itself (`gantry__…`), not by a connector.
- **Interaction** — a pending decision the user must make (permission, access request, connector suggestion, MCP elicitation, skill or memory proposal). One mechanism serves all of them.
- **Skill** — a text-only `SKILL.md` playbook injected into context when relevant. **Memory** — a short, user-visible fact or preference carried across chats.
- **Artifact** — a versioned piece of content (document, code, page, diagram, component) shown in the panel beside the chat.
