# 07 — Repository structure

Three top-level folders: `desktop/` is the product (everything that ships in the binary), `web/`
holds the two static sites, `docs/` the plan. One Cargo workspace and one pnpm workspace, both
rooted at the repository root, so every command runs from there. Names below are the canonical
ones used across the plan. Reorganised 2026-09-07 (session 5) from a flat root.

## Where things go

| If you are adding… | Put it in… | And also… |
|--------------------|------------|-----------|
| A first-party connector | `desktop/connectors/<id>/` with `Cargo.toml` | add the crate to `[workspace].members` and to `gantry-connectors` dependencies + `native/registry.rs` |
| A bundled MCP connector | `desktop/connectors/<id>/` with `manifest.json`, `icon.svg`, `README.md` | nothing else; `build.rs` embeds it |
| A connector's custom settings panel | `desktop/connectors/<id>/ui/index.tsx` | set `settings_ui` in the manifest |
| A bundled skill | `desktop/skills/<name>/SKILL.md` (+ `references/*.md`) | `cargo xtask validate-skills`; `gantry-agent`'s `build.rs` embeds it |
| A new artifact type | a renderer in `desktop/frontend/src/features/artifacts/renderers/` and an entry in both registries (`gantry-agent/src/artifacts/registry.rs`, `features/artifacts/registry.ts`) | if executable, a mount in `desktop/artifact-runtime/src/`; a line in `desktop/assets/prompts/core.md` |
| A library artifacts may import | `desktop/artifact-runtime/src/react/modules.ts` | the allowlist line in `desktop/assets/prompts/core.md` and `desktop/skills/artifact-authoring/references/react-runtime.md` |
| A runtime tool (`gantry__…`) | `desktop/crates/gantry-agent/src/runtime_tools/` | tier `app`; its card in `desktop/frontend/src/features/interactions/` if it needs a decision |
| A colour, size, radius or duration in the app | `desktop/frontend/src/styles/tokens.css` and the table in 15 §3–§6, §10, in the same commit | the contrast script must still pass |
| A new UI component | a primitive in `desktop/frontend/src/components/ui/` or a composite in `desktop/frontend/src/components/gantry/` | its gallery entry under `features/gallery/entries/` |
| A settings key | `gantry-core/src/settings.rs` with a default | its section component under `desktop/frontend/src/features/settings/` |
| A new model provider client | `desktop/crates/gantry-providers/src/<name>/` | a row in the normalization table in 02 and fixtures under `tests/fixtures/<name>/` |
| A new IPC command | `desktop/app/src/commands/<area>.rs` | run `cargo xtask gen-bindings`; add a hook in `desktop/frontend/src/lib/ipc/hooks/` |
| A new event kind | `gantry-core/src/event.rs` | handle it in `runStore.applyBatch` and, if persisted, in the persister |
| A schema change | `desktop/crates/gantry-store/migrations/NNNN_name.sql` | update the repository and the table list in 06 |
| A permission rule | `desktop/crates/gantry-agent/src/permissions/` | update the matrix in 04 |
| A prompt change | `desktop/assets/prompts/` | bump the core version; the prompt fixture test in `gantry-agent` |
| Branding | `desktop/assets/branding/` | regenerate `desktop/app/icons/` with `pnpm tauri icon` |
| Site copy | the page under `web/site/src/pages/`, or a Markdown file under `web/site/src/content/` for blog, changelog and docs | nothing else; Pages builds and deploys on push |
| A connector on the website | one entry in `web/site/src/data/connectors.ts` (the directory, its page and the logo cloud follow) | nothing: the build finds its Simple Icons mark or uses initials; a cleared file in `web/site/public/connectors/` overrides |
| A site colour or font | `web/site/src/styles/theme.css` | nothing |
| A decision that changes this plan | `docs/decisions/NNNN-title.md` | edit the affected plan document in the same commit |

## Notes on specific files

- **The root `package.json`** is the pnpm workspace root and nothing more: `pnpm dev`, `build`, `typecheck`, `lint`, `test`, `fonts` and `design:contrast` forward to `@gantry/frontend`; `pnpm format` runs prettier over the whole repository; `pnpm tauri` runs the Tauri CLI, which locates `desktop/app/tauri.conf.json` by searching below the working directory and runs `beforeDevCommand`/`beforeBuildCommand` at the root. `tauri-action` in the workflows finds the config the same way.
- **`Cargo.toml` (workspace).** Native connector crates are listed explicitly because `desktop/connectors/*` also holds manifest-only folders. Shared dependency versions live in `[workspace.dependencies]`. `target/` stays at the root.
- **`desktop/crates/xtask`** finds the workspace root by walking up to `Cargo.lock`, so it does not care how deep it sits. `gen-bindings` writes `desktop/frontend/src/bindings.ts`; `desktop/app/src/lib.rs` exports to `../frontend/src/bindings.ts` relative to the crate on every debug start and its `gen_bindings` test diffs against the same file.
- **`desktop/crates/gantry-connectors/build.rs`** and **`desktop/crates/gantry-agent/build.rs`** re-run when any manifest or `SKILL.md` changes (`cargo:rerun-if-changed` per file) and fail the build with the schema error and the offending path. Both reach their folders with `../../connectors` and `../../skills`.
- **`pnpm-workspace.yaml`** lists `desktop/frontend` and, from M5, `desktop/artifact-runtime`; the app's `build` script runs the runtime build first so `src/generated/artifact-runtime.html` is fresh (it is gitignored and regenerated).
- **`desktop/frontend/vite.config.ts`** aliases `@/` to `src/`; when custom connector panels arrive it adds `../connectors` to `server.fs.allow` and the two `import.meta.glob` roots relative to `src/features/connectors/`.
- **`desktop/frontend/tests/schemas.test.ts`** reads `../../schemas` and `../../connectors`, so the schema and the manifests stay next to the Rust code that embeds them while the test runs under vitest with the frontend's dependencies.
- **`desktop/app/tauri.conf.json`** points `frontendDist` at `../frontend/dist` and `bundle.icon` at the generated `icons/` set; the sources stay in `desktop/assets/branding/app-icon/` so the identity work has one home.
- **`web/client-metadata/client-metadata.json`** is deployed to `id.oljo.dev`; its `client_id` must equal its own URL exactly (03 §7). Changing that URL invalidates every OAuth registration users have made, which is why the folder has a README saying so.
- **`web/site/`** keeps its own lockfile and stays out of the application's pnpm workspace so Cloudflare Pages can build it with root directory `web/site` (14 §1).
- **`desktop/assets/*.toml`** and **`desktop/assets/prompts/*.md`** are embedded with `include_str!` and parsed at startup, so tuning judge defaults, guardrails or prompt wording is a data change, not a code change; the core prompt still carries a version number.
